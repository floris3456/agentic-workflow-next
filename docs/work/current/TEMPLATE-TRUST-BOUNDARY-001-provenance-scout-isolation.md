### AWT-001 package provenance

Schema-1 generation trusted the supplied local Git object database, so local
commit existence/ancestry did not prove canonical provenance. New schema-2 source
closes that gap:

- `scripts/change-package-lib.mjs` is the shared offline verifier used by
  generation, application, and ledger validation.
- The supplied checkout's `origin` must match `source-lock.json`'s canonical
  `https://github.com/<owner>/<repo>.git` identity.
- Requested developer/web bases must equal the source-lock review bases.
- Generation creates a sterile temporary bare Git repository, fetches canonical
  `developer` and `web-orchestration` tips directly from the canonical URL, and
  requires the requested heads to equal those freshly fetched tips.
- Patch bytes and changed paths are produced only from that fetched canonical
  object database. The caller's local objects are not package evidence.
- The schema-2 manifest embeds the exact source-lock snapshot, its digest, fetched
  heads, exact ranges, changed paths, per-patch SHA-256 values, and a versioned
  package SHA-256 binding the manifest core and both raw patch streams.
- Offline validation recomputes those relationships and bindings. Historical
  schema-1 packages remain integrity-compatible but explicitly return
  `provenanceVerified: false` rather than being reclassified.
- Focused tests cover deterministic schema-2 generation, deceptive origin, wrong
  locked base, stale/local-only head, source-lock/patch/package tampering, legacy
  schema-1 compatibility, and downstream dry-run/application boundaries.
