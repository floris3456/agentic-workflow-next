# Task review and steering

## Trigger

Use after remote review identifies completion, a failed requirement, an external blocker, or a better direction.

## Procedure

1. Form conclusions from remote evidence and independent reasoning.
2. If acceptable, record substantive-approval SHA and move to finalization.
3. If the same goal remains, steer the existing task even when strategy changes radically.
4. Require `Changed approach` to describe old/new route, steering source, and treatment of prior work.
5. Create a new task only when the intended outcome materially changes.
6. Prefer corrective commits or `git revert`; avoid shared-history rewriting.
7. Do not count external blockers or brief/tool defects as Luna failures.
8. If synchronization breaks, stop implementation and use synchronization recovery.
9. Persist consequential steering and review conclusions in task context.
