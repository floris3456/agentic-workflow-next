# MCP-ON repository scouting

## Trigger

Use when likely code symbols or implementation areas are unknown.

## Procedure

1. Use jCodeMunch only for symbol and relationship orientation.
2. Scout the minimum needed to identify likely files, components, interfaces, and tests.
3. Do not use scouting output as exact post-change evidence.
4. Read exact non-code and broader code context through connected GitHub MCP.
5. If scouting contradicts GitHub, GitHub wins.
6. Do not repair index freshness during unrelated work unless agent-system maintenance was commissioned.
7. Evidence or research may be excluded from indexing by design; read it deliberately through exact GitHub evidence when required.
