# Finalization review

## Trigger

Use after the implementing developer pushes finalization.

## Procedure

1. Compare substantive-approval SHA to finalization SHA.
2. Confirm task-progress was deleted; inspect its final pre-deletion form if needed.
3. Confirm durable information reached AS-BUILT, deviations, design, decisions, or other correct homes.
4. Confirm records remain truthful and temporary narrative was not copied wholesale.
5. Confirm no unexpected product code or behavior entered finalization.
6. If substantive changes exist, reopen the same task and resume normal review.
7. Record the exact final `developer` SHA.
8. Ask whether that exact SHA should enter `main`; do not promote without explicit approval.
