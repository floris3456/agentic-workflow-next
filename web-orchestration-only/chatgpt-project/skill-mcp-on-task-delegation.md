# MCP-ON task delegation

## Trigger

Use when exact evidence is sufficient for a bounded implementation task.

## Procedure

1. Load `skill-shared-task-design.md` and `skill-shared-public-safe-persistence.md`.
2. Establish the exact remote `developer` start SHA and ensure one repository-mutating task and one open bridge-control issue at a time. Finish the prior task and close its control issue before creating another.
3. Update web task context before consequential delegation.
4. Load the routing skill before every initial agent selection. Select Luna by default and create its routing record before preparing the command; use the routing policy before selecting Sol.
5. Create one public-safe issue without the control label. Use a human-readable title and body without a command marker.
6. Generate a fresh command UUID and sequence `1` `start` envelope. Set `arguments.brief` to the exact public-safe brief, set `arguments.agent` explicitly to `luna` or `sol`, and set `expected` to the exact remote `developer` SHA and ref `developer`.
7. Include task ID, start SHA, scope, constraints, records, checks, stop conditions, the five-field response contract, immediate task-progress creation, and exact preservation of the public-safe brief in `arguments.brief`.
8. Before publication, persist the issue URL/number and exact envelope as pending state `prepared`. Confirm that commit remotely, apply `<bridge-control-label>`, then post the preserved marker from the configured authorized identity. Record the exact comment URL, state `posted`, and initial route-command ref after readback.
9. Never send private raw chat wording. If preparation or labeling definitely fails before publication, mark the command `cancelled` when possible and close the orphaned issue. If comment publication/readback is ambiguous, keep the issue and pending envelope intact and enter delegation recovery.
10. Wait for a correlated status from `<bridge-bot-login>`. `accepted` is not execution success. A terminal `succeeded` result proves session creation and prompt delivery, not implementation completion.
11. Do not use bridge/OpenCode output to read or review the repository. Establish implementation facts independently from remote GitHub.
12. Use delegation recovery before reposting or replacing an ambiguous command.
