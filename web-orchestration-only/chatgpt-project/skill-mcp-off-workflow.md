# MCP-OFF public-web workflow

## Trigger

Use for public GitHub lookup, analysis, visible review, or bounded future task
preparation while MCP capabilities are unavailable or intentionally off.

## Procedure

1. Navigate through the public web to
   `https://github.com/<owner>/<repository>`. Establish branch/ref and exact SHA
   before relying on a file, commit, history, compare, raw, check, or API page.
2. For a quick lookup, inspect the narrow exact page and answer. Load the separate
   MCP-OFF scouting Source only when likely areas are unknown.
3. Review only evidence the public interface exposes exactly. For a change,
   establish exact base/head and inspect the complete visible range plus required
   context. Task records and developer reports remain navigation.
4. Scale review proportionally: focused evidence for small low-risk work;
   affected boundaries and relevant visible checks for medium work; broader
   exact-range/context review for large work; and direct inspection of every
   manageable relevant file/diff for high-stakes work. State any material public
   evidence gap instead of pretending it was verified.
5. If implementation is needed and the human did **not** ask for a prompt to a
   different execution context, prepare a public-safe bounded future task with
   stable ID, current exact start SHA, outcome, scope, constraints, records,
   proportional checks, stop conditions, and the six fields `Status:`, `Handoff
   developer SHA:`, `Files changed:`, `Checks + perceived results:`,
   `Blockers/decisions:`, and `Task record:`. Do not claim it was sent or started.
   If the human **did** ask for a prompt to a new MCP-ON chat, MCP-OFF chat, or
   direct OpenCode session, use the cross-mode prompt-creation Source instead.
   Its destination-aware handoff format owns the generated prompt; carry forward
   the capability, evidence, safety, authority, and public-safety limits from this
   workflow, but do not inject this generic future-task schema or developer
   response contract unless the human explicitly requests that format.
6. Do not create/control a bridge issue, invoke or imply an OpenCode Scout,
   delegate, write task/routing state, answer a local developer interaction, or
   claim promotion. Public-web navigation and reasoning are the complete action
   surface in this mode.
7. When MCP-ON becomes available, first recheck remote state and open control
   issues, reconcile consequential MCP-OFF decisions into public-safe task
   context, update any stale brief, then use the MCP-ON workflow.

Remote GitHub remains authoritative. Label unresolved facts and capability limits
plainly; an unavailable action is not an invitation to simulate it.
